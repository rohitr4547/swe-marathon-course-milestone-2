## Rules

### C4. User groups and mentions

`GroupObj = {id, handle, name, member_user_ids: [...]}`. Request bodies use `user_ids`; responses
use `member_user_ids` and never `members`. A handle matches `^[a-z0-9-]{1,32}$`.

C4.1 **Create and list.** Any workspace member may `POST /api/workspaces/{slug}/groups` with
`{handle, name, user_ids}`: `201` and `{group}`. `GET /api/workspaces/{slug}/groups` returns `200`
and `{groups: [...]}`.

C4.2 **Create errors.** A handle already used in the workspace returns `409`. A bad or missing
handle, or a `user_ids` entry that is not a workspace member, returns `400`. A caller who is not a
workspace member gets `403` (on GET too).

C4.3 **Update.** `PATCH /api/workspaces/{slug}/groups/{handle}` with any subset of
`{name, user_ids}` returns `200` and `{group}`, for the group's creator or the workspace owner only
(others `403`). An unknown handle returns `404`.

C4.4 **@group-handle.** In a message, `@<handle>` adds every group member who is also a member of
the destination channel, except the author.

C4.5 **@here.** `@here` adds every channel member except the author who currently has an open
WebSocket on any node. Once that socket closes, they stop being added within 3 seconds.

C4.6 **Dedupe.** Ids from `@username`, `@group-handle`, `@here` and `@channel` are merged and
deduplicated, and the author is never in `mentions` (so mentioning yourself never adds to your
own `mention_count`).

C4.7 **Delete.** `DELETE /api/workspaces/{slug}/groups/{handle}` by the creator or the workspace
owner returns `200` and `{"deleted": true}`, and again `200` if repeated. Others get `403`. A
deleted group is no longer listed.

Every request must answer within 5 seconds.
