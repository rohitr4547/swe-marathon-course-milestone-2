# E.2: The IRC gateway

Rule group: **E2**.
Check: `bash /spec/e/checks/check_e_2.sh`. The rule numbers below match its output.

Do not start this step until `check_e_1.sh` prints `RESULT: 9 passed, 0 failed`.

## Uses

| Function | Used here for |
|---|---|
| `user_for_token(token)` | `PASS <token>` |
| `join_channel(user, channel_id)` | `JOIN` follows the web join rules |
| `get_workspace(slug)` | Mapping `#<workspace-slug>/<channel-name>` to a channel |

## Adds

| Function | What it does |
|---|---|
| `irc.py: handle(reader, writer)` | One asyncio connection: registration, commands, numerics |

The server prefix is `huddle`. Every line ends with `\r\n`. A numeric reply looks like
`:huddle <code> <nick> <params> :<text>`. The gateway listens on `0.0.0.0:6667`.

## Rules

### E2. IRC gateway

E2.1 **Bad password.** The client sends `PASS <token>`, `NICK <nick>`, `USER <user> 0 * :<real
name>`. Once both `NICK` and `USER` have arrived, a missing or unknown token gets `464` and the
connection closes.

E2.2 **Registration.** With a valid token the server sends numerics `001`, `002`, `003`, `004`,
`005`, then `422` (no MOTD).

E2.3 **Join.** `JOIN #<workspace-slug>/<channel-name>` (a literal `/`) runs the web join rules and
replies `:<nick>!<user>@huddle JOIN #slug/name`, then `353 <nick> = #slug/name :<usernames>`, then
`366 <nick> #slug/name :End of /NAMES list` (`332`/`331` may also be sent). A hyphenated name such
as `#slug-general`, an unknown channel, or a join the rules forbid gets
`403 <nick> <name> :No such channel`.

E2.4 **Other commands.** `PING :<token>` gets `:huddle PONG huddle :<token>`. `PONG`, `NAMES`, `WHO`,
`LIST`, `TOPIC` and `MODE` are accepted and never get `421` (a minimal reply or none is fine). Any
other unknown command gets `421 <nick> <command> :Unknown command`.

E2.5 **Nick collision and QUIT.** A `NICK` already used by another connection gets
`433 * <nick> :Nickname is already in use`, the connection stays open, and a new `NICK` then
completes registration. `QUIT` closes the connection without sending an `ERROR` line.

Every request must answer within 5 seconds.
