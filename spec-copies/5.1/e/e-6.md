## Uses

| Function | Used here for |
|---|---|
| `static/index.html` from E.4 and E.5 | Layout, hooks, logged-in state |
| Message, reply, reaction, edit and delete routes | The UI calls them; WebSocket events keep the view current |

## Adds

UI behaviour only. Each message row is a `message` element inside `message-list` holding
`message-avatar`, `message-author`, `message-time` (human-readable), `message-body`, and a toolbar
shown on hover with `edit-message-btn`, `delete-message-btn`, `open-thread-btn` and
`reaction-button`. Editing shows an `edit-message-input` that saves on Enter; an edited message
shows `message-edited` (for example the text "edited"); a message with replies shows
`reply-count` (for example "1 reply", "2 replies").

## Rules

### E6. Messages, threads and reactions

E6.1 **Post.** Typing in `message-input` and clicking `send-btn` posts the message; its row appears
with avatar, author name, readable time and body.

E6.2 **No blank posts.** An empty or blank `message-input` posts nothing.

E6.3 **Edit.** The hover toolbar's `edit-message-btn` edits a message in place; the new body and a
visible `message-edited` indicator show, and both survive a hard page reload.

E6.4 **Threads.** `open-thread-btn` opens the thread in `thread-panel`, a pane to the right of the
message list; a reply sent with `thread-input` and `thread-send` shows in the panel and the parent
row's `reply-count` reads "1 reply". `close-thread` hides the panel.

E6.5 **Reactions.** `reaction-button` opens `emoji-picker`, a grid of at least six `emoji-option`
buttons (never a `prompt()`); choosing one shows a `reaction-chip` with the emoji and count `1`,
saved through the API.

E6.6 **Delete.** `delete-message-btn` deletes the message without any dialog; its row disappears.

E6.7 **Layout.** At 1280x900 the page is three panes: a coloured `sidebar` (not white or
transparent; it holds the workspace name and `#`-prefixed channel names), the message pane with a
header carrying the channel name and topic, and the on-demand thread panel on the right.

Every request must answer within 5 seconds.
