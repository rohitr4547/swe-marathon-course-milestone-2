Check: `bash /spec/e/checks/check_e_5.sh`. The rule numbers below match its output.

## Uses

| Function | Used here for |
|---|---|
| `static/index.html` and `static/app.js` from E.4 | All hooks below already exist in the first HTML; `api()` and `init()` |
| `/api/auth/*`, `/api/workspaces`, `/api/workspaces/{slug}`, channel routes | The UI is a client of the same API |

## Adds

UI behaviour only, as functions in `app.js` bound once in `init()`: sign-up and login, workspace
creation, channel creation and switching, logout. Never open `alert`, `confirm` or `prompt`; show messages in the page instead.

## Rules

### E5. Sign-up, workspaces and channels

The auth form has inputs `name="username"` and `name="password"` (and optionally
`name="display_name"`), and a `data-mode` attribute that is `"signup"` or `"login"`;
`auth-toggle` switches the mode and the form starts in `"signup"` mode. The workspace form has
inputs `name="name"` and `name="slug"` and a submit button. The channel form has an input
`name="name"`.

E5.1 **Bad sign-up.** Submitting the sign-up form with an invalid username (such as `bad name!`)
shows the API's error as visible, non-empty text in `auth-error` and stores no token.

E5.2 **Sign-up logs in.** A valid sign-up logs the user in: the token is stored in `localStorage`
under `huddle.token` (and the page accepts `?token=<bearer>` in the URL), `auth-form` is hidden,
and `current-user` shows the username. Loading `/` with a stored token (or `?token=`) skips the auth
form and, within 2 seconds, opens the user's first workspace from `GET /api/workspaces` with every
channel the user can see as a `channel-entry` in the sidebar; E.6 starts from exactly this.

E5.3 **Create a workspace.** A user with no workspace sees `workspace-create-form` (or opens it
with `empty-state-create-workspace`); submitting it creates the workspace, `workspace-header`
shows its name, and the sidebar lists `#general` as a `channel-entry` with `data-channel-id` and
`data-channel-name="general"` on the clickable element, labelled with a leading `#`.

E5.4 **Create a channel.** `new-channel-btn` opens `create-channel-form`; `create-channel-submit`
creates the channel, adds its `channel-entry` and opens it (`channel-title` shows its name). A
duplicate name shows the API's `409` as visible text in `create-channel-error` and adds no entry.

E5.5 **Switch channels.** Clicking a `channel-entry` opens that channel: `channel-title` shows its
name and `channel-topic` its topic. A channel with no messages shows visible, non-blank text in
`channel-empty-state`.

E5.6 **Logout and login.** `logout-btn` clears the stored token and shows `auth-form`. Logging back
in (login mode) with the same username and password restores the same workspace and channels.

E5.7 **No dialogs.** None of these flows opens a browser dialog.

Every request must answer within 5 seconds.
