# E.4: Web UI: page, hooks and colours

Rule group: **E4**.
Check: `bash /spec/e/checks/check_e_4.sh`. The rule numbers below match its output. The check
drives the headless Chromium installed with Playwright.

Do not start this step until `check_e_3.sh` prints `RESULT: 4 passed, 0 failed`.

## Uses

| Function | Used here for |
|---|---|
| `server.py` routes | Serve `static/index.html` at `GET /` on every node; the UI calls the same `/api` routes |

## Adds

| File | What it holds |
|---|---|
| `static/index.html` | The whole single-page UI: inline CSS and plain JavaScript, no external files |

## Rules

### E4. The page

E4.1 **Served everywhere.** `GET /` on `8000`, `8001` and `8002` returns `200` with
`Content-Type: text/html` and the UI page.

E4.2 **Hooks in the first HTML.** The HTML served at `GET /` (before any JavaScript runs) contains
an element with each of these `data-testid` values: `auth-form`, `auth-submit`, `auth-toggle`,
`workspace-create-form`, `empty-state-create-workspace`, `join-workspace-form`,
`join-workspace-submit`, `channel-list`, `dms-list`, `new-channel-btn`, `current-user`,
`logout-btn`, `workspace-header`, `workspace-settings-btn`, `workspace-settings-close`,
`workspace-name-input`, `workspace-join-mode`, `workspace-general-submit`, `channel-title`,
`channel-topic`, `channel-settings-btn`, `channel-settings-title`, `channel-settings-close`,
`channel-members-list`, `channel-add-member-form`, `channel-add-member-input`,
`channel-add-member-submit`, `channel-topic-input`, `channel-topic-submit`,
`archive-channel-btn`, `unarchive-channel-btn`, `create-channel-form`, `create-channel-private`,
`create-channel-submit`, `create-channel-cancel`, `message-list`, `message-input`, `send-btn`,
`thread-panel`, `thread-input`, `thread-send`, `close-thread`, `settings-tab-members`,
`settings-tab-invitations`, `settings-tab-general`, `settings-pane-members`,
`settings-pane-invitations`, `settings-pane-general`, `create-invitation-btn`,
`create-invitation-form`, `create-invitation-submit`, `invitations-list`, plus the extra hooks
`auth-error`, `create-channel-error`, `channel-empty-state` and `sidebar` (the coloured left pane).
These are created when data renders: `channel-entry`, `channel-member-row`, `message`,
`message-body`, `open-thread-btn`, `reaction-button`, `reaction-chip`, `emoji-picker`,
`emoji-option`, `member-row`, `role-badge`, `role-select`, `invitation-code`,
`join-workspace-error`.

E4.3 **DOM ids.** The first HTML also has elements with `id` `auth-modal`, `create-channel-modal`,
`channel-settings-modal`, `workspace-settings-modal` and `create-invitation-form`.

E4.4 **Button roles.** In the first HTML each of these buttons has `data-button-role`:
`primary` on `auth-submit`, `send-btn`, `thread-send`, `create-channel-submit`,
`join-workspace-submit`, `workspace-general-submit`, `create-invitation-submit`,
`channel-topic-submit`, `channel-add-member-submit`; `danger` on `archive-channel-btn`,
`logout-btn`; `secondary` on `new-channel-btn`, `create-invitation-btn`, `unarchive-channel-btn`,
`create-channel-cancel`, `close-thread`, `channel-settings-close`, `workspace-settings-close`,
`channel-settings-btn`, `workspace-settings-btn`.

E4.5 **Exact colours.** At 1280x900, in its resting state, every one of those buttons has computed
`color` `rgb(255, 255, 255)`, no `background-image`, and `background-color` exactly
`rgb(0, 122, 90)` (`#007a5a`) for primary, `rgb(224, 30, 90)` (`#e01e5a`) for danger and
`rgb(18, 100, 163)` (`#1264a3`) for secondary. Style them with one rule per role, for example
`[data-button-role="primary"] { background-color: #007a5a; color: #fff; background-image: none; }`.

Every request must answer within 5 seconds.
