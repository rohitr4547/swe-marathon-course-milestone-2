## Rules

### C2. DMs and files

C2.1 **Open a DM.** `POST /api/dms` with `{user_id}` returns `200` and `{channel_id}`. The same
`channel_id` comes back when the other person calls it with the first person's id, and on every
repeated call, on any node.

C2.2 **DM access.** Both people can post (`201`) and read history in the DM channel through the
normal message routes. Anyone else gets `403` on both.

C2.3 **DM errors.** An unknown `user_id` returns `404`. A missing or non-integer `user_id` returns
`400`.

C2.4 **Upload.** `POST /api/files` with `multipart/form-data` holding one `file` part returns
`201` and `{file: FileObj}`, where `FileObj = {id, uploader_id, filename, content_type, size,
created_at}`: `uploader_id` is the caller, `filename` and `content_type` are the part's filename
and Content-Type, `size` is the byte count, and `created_at` is UTC ending in `Z`.

C2.5 **Metadata.** `GET /api/files/{id}` returns `200` and `{file}` for any logged-in user on any
node.

C2.6 **Download.** `GET /api/files/{id}/download` returns the exact uploaded bytes with the
uploaded `Content-Type` and a `Content-Disposition` header containing the filename (for example
`attachment; filename="notes.bin"`).

C2.7 **Size limit.** An upload over 10 MiB (10 485 760 bytes) returns `413`. Use
`client_max_size` of at least 11 MiB in aiohttp so the request reaches your handler.

C2.8 **Attach to a message.** `POST /api/channels/{id}/messages` with `file_ids: [<id>]` attaches
the caller's own files: the response and history list them as `FileObj`s in the message's `files`.
A file that is already attached, belongs to someone else, or does not exist returns `400`.

Every request must answer within 5 seconds.
