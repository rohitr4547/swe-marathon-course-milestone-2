# D.3: Delivery speed under load

Rule group: **D3**.
Check: `bash /spec/d/checks/check_d_3.sh`. The rule numbers below match its output.

Do not start this step until `check_d_2.sh` prints `RESULT: 3 passed, 0 failed`.

## Uses

| Function | Used here for |
|---|---|
| Architecture rules 2, 3 and 5 | One short transaction per write; delivery polling every 0.05 s |

## Adds

Nothing new. If these rules fail, look for a slow write path (opening a new database connection per
request, `time.sleep` in a handler, holding the transaction while building JSON) or a slow delivery
loop (polling less often than every 0.05 s, one query per event instead of one per channel).

## Rules

### D3. Speed under load

The check runs six writers at once (two through each node) posting 60 messages to one channel,
with one subscriber on each node. Latency is measured from just before a post is sent to the
moment a subscriber receives its `message.created` frame.

D3.1 **Nothing lost.** Every post returns `201`, and the subscribers miss at most 1% of the
expected `message.created` frames (60 posts × 3 subscribers).

D3.2 **Median latency.** The median delivery latency is at most 300 ms.

D3.3 **Tail latency.** The 95th percentile delivery latency is at most 800 ms.

Every request must answer within 5 seconds.
